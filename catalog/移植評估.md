# 圖鑑效果移植評估（含 counter、karaoke、quote 試移植結果）

## 1. 圖鑑 HTML 的 DRAW 是什麼

`DRAW[id](ctx, w, h, t, st, canvas, dpr)`：每個效果是一個 Canvas 繪圖函式，**畫整張畫面**（`clear` 先塗不透明底色），時間 `t` 由網頁自己的 requestAnimationFrame 提供，多數用 `t%T` 自己循環。要接進 HyperFrames，需要三個轉換：

| 圖鑑原版 | 移植版 |
|---|---|
| 寫死的字、數字、顏色（例：標籤「本月新增使用者」、12480、A/B 色） | 參數 `P`（預設值＝原版）＋調色盤 `C`（可套主題色） |
| `t%T` 無限循環 | 本地時間 `tt` 從 0 開始、播完停在最後一格 |
| `clear` 塗不透明底 | `C.clear`：可選透明底，才能疊在版面上 |
| 網頁的 rAF 驅動 | GSAP 時間軸驅動（`fxMount`：一個隱形 tween 帶著 `tt`，`onUpdate` 重畫），任何跳幀都能重現 |

## 2. 148 種的可移植性（掃描 DRAW 原始碼）

- **140 種是純函式**（只看 `t`，沒有 `Math.random`、沒有累積狀態、沒有時鐘）→ 可直接照上面規則移植。
- **8 種需要額外處理**：`flow`（隨機＋拖尾累積，無法跳幀）、`sphere`、`ptext`、`gooey`、`zoomtext`（粒子或點陣初始化存在狀態裡，要改成用種子亂數）、`lightsweep`、`softdiag`、`kenburns`（用離屏快取）。
- **14 種組合疊加**（`cmb_*`）是呼叫其他效果的 `LY` 疊層，要等被呼叫的效果都移植完才能做，並多做一個疊層函式。
- 34 種數字或標題用 `Unbounded` 字型（本機沒有，會退回預設字型）：移植時要決定改用 Noto Sans TC。
- 75 種有 `t%T` 循環，移植時要決定「播完停住」還是「循環」。

## 3. 試移植驗證（2026-10-22）

三個效果各做一份「純函式＋參數」版本（catalog/fx/ 下的 counter.js、karaoke.js、quote.js），驗證四件事，全部通過：

| 驗證 | 結果 |
|---|---|
| 預設參數下與原版逐像素比對（1130×760，21 個時間點） | **0 個位元組不同**（counter 8 幀、karaoke 6 幀、quote 7 幀） |
| 參數有效、透明底有效、主題色盤有效 | 通過（左上角 alpha=0；換色盤後像素改變） |
| 放進 HyperFrames 並跑 `hyperframes check` | 0 錯誤 |
| 跳幀確定性：6 個時間點分別用「順向／亂序／反向」跳過去，3 張 canvas 內容比對 | 全部一致 |

另外用 `g_fx` 範本在睡眠測試片上實際看過畫面：效果疊在主題面板上，用通用主題的紫色、套 Noto Sans TC，和字幕時間對得上（見 試作專案 的抽幀）。氣象案重建後動畫仍為 2444 個、雜湊相同，沒有被影響。

## 4. 做法

1. 新增 `catalog/fx_runtime.js`（調色盤、`fxDefine`、`fxMount`）與 `catalog/fx/<id>.js`（一效果一檔，預設參數＝原版）。
2. 新增核心範本 `g_fx`：`params.v.fx` 填圖鑑 id，`params.v.params` 填效果參數，`line／key` 決定從哪句字幕開始。建置時自動把已移植的效果與主題調色盤帶進頁面。
3. 比對用的原版 DRAW 逐字擷取在 `catalog/fx/_original_draw.js`，比對頁是 `catalog/fx/_compare.html`；每移植一個效果就加進比對清單，**逐像素 0 差異才算完成**。

三個效果這次是手工移植加驗證。依原始碼大小（平均每個 DRAW 約 555 字元）粗估：

| 範圍 | 數量 | 估計 |
|---|---|---|
| koubo 已對照到的「對應」12 項涉及的效果（先做這批） | 約 12 種 | 0.5～1 天 |
| koubo 對照到的全部 30 種（其中 27 種純函式） | 30 種 | 1.5～3 天 |
| 其餘純函式 | 約 110 種 | 5～9 天（可寫轉換腳本處理 `clear`／常數／`t%T` 等機械部分，人工只決定要開放哪些參數） |

最費工的不是改寫程式，而是**決定每個效果要開放哪些參數**（哪些字、數字、顏色該讓內容決定）與**把 koubo 的場景改成呼叫它們**。

## 7. 第二批移植結果與是否取代手寫版（2026-10-22）

**移植結果**：「對應」12 項涉及 9 種圖鑑效果（counter、karaoke、quote 之外再加 charfall、kinetic、filmfx、stamp、routemap、chart）全部移植完成。比對頁 [_compare.html](fx/_compare.html) 共 9 種、60 個時間點，**預設參數下與圖鑑原版逐像素 0 差異**；`check_effects.py` 現在也會檢查每個已移植效果都列在比對清單內。

**取代決定：目前一項都不取代。** 逐項比對功能後，圖鑑版是「整張卡片」，手寫版是「可放在任意位置的元件」，兩者不等價：

| 現有手寫版（呼叫量） | 對應圖鑑效果 | 為什麼不取代 |
|---|---|---|
| bignum 數字元件（7 處、5 個範本） | counter | 手寫版可指定位置、字級、單位、結束淡出；圖鑑版是整張卡（含標籤、進度條、徽章），放不進既有位置 |
| stamp 邊框章（6 處、5 個範本） | stamp | 手寫版可指定位置、旋轉、顏色、大小並有抖動；圖鑑版固定整張報紙底與固定位置 |
| mpath／follow／followT 地圖路徑（21 處、9 個範本） | routemap | 手寫版畫在真實地圖座標上並帶著颱風圖示；圖鑑版是抽象點陣圖、固定 5 個點 |
| 字幕逐字高亮 | karaoke | 手寫版是全片共用的 DOM 字幕條，換成 canvas 會動到所有影片，沒有收益 |
| #opener 開場標題 | charfall、kinetic | 手寫版與開場副標、轉場綁在一起；圖鑑版適合當內容卡，不適合換開場 |
| #fx 顆粒暗角 | filmfx（scene:false） | 功能可等價，但顆粒外觀會變，所有舊案要重新驗收，目前沒有必要 |
| g_number | counter | 手寫版支援單位、區間文字（如 7～9）、補充說明；圖鑑版沒有 |
| g_bars | chart | 手寫版有標籤與數值、橫向可比較；圖鑑版長條沒有標籤 |
| g_quote | quote | 近乎等價，但手寫版多了頁首標籤與主題色，換掉收益很小 |

**改採「新增」而不是「取代」**：9 種移植版都能用核心範本 `g_fx` 直接呼叫（`params.v.fx` 填圖鑑 id，等於同時記錄用了哪個效果）。氣象案已驗收、是迴歸基準，維持不動。

**之後會變成可取代的條件**：圖鑑版補上手寫版有的能力（單位／區間文字、標籤、可指定位置與大小）。要做的話建議先擴充 counter 與 chart 的參數，再重做驗收。

## 8. 擴充 counter、chart 並重評取代（2026-10-22）

**擴充內容**（預設值都不改變畫面，所以原版比對仍 0 差異）：
- counter：單位 `unit`、不跳動的區間文字 `text`（如 7～9）、置中 `align`、字級 `numSize`、數字顏色 `numColor`、補充說明 `note`、是否畫進度條 `bar`、數字延後開始 `delay`。
- chart：橫向模式 `orient:"h"`、標題 `title`、標籤 `labels`、數值 `values`、依序換色 `colors:"cycle"`、每根各自的開始時間 `delays`（對上各自的字幕）；橫向數值文字會自動留空間，不再被切掉。
- g_fx：`lead`（標籤從場景第一句出現、數字等關鍵字）、`delays`（逐項字幕時間）、播放長度自動延長到場景結束。

**驗證**：9 種效果、60 個時間點，擴充後預設參數下仍與圖鑑原版**逐像素 0 差異**（最終版本重跑確認）。

**同內容並排評估**（手寫版 A、圖鑑版 B，同一支片、同一字幕時間點；見 測試案 資料夾的並排圖）：
| 內容 | 結果 |
|---|---|
| 區間文字「7～9 小時」 | 外觀接近；B 的標籤字色較灰、細 |
| 數字 30％＋補充說明 | 外觀接近；A 數字有發光，B 沒有 |
| 三筆橫向長條（標題、標籤、數值、換色、逐根對字幕） | B 更好：A 的「2,500 萬」數值會折成兩行，B 不會 |

**取代決定**：
- **取代 g_number、g_bars**：現在兩個範本改由 counter／chart 繪製；舊手寫版保留為 `g_number_legacy`、`g_bars_legacy`，要沿用舊外觀的專案可指定。已重建睡眠、財經兩個測試案，`hyperframes check` 皆 0 錯誤。
  - 已知差異：g_number 不再支援起始值 `from`；標籤字色與字重、數字發光與手寫版略有不同。
- **仍不取代**：bignum 數字元件、stamp 邊框章、地圖路徑（mpath／followT）、字幕逐字高亮、開場標題、底片顆粒暗角、g_quote。理由同第 7 節（功能不等價或會動到全片，收益太小）。
- 氣象案不受影響（不使用 g_number、g_bars），本輪沒有重跑氣象案的動畫指紋比對。

## 9. 其餘純函式效果移植（2026-10-22）

koubo 在 effect_map 對照到的 30 種圖鑑效果，已移植 27 種；沒移植的 3 種是**有狀態**（kenburns、softdiag、lightsweep，用離屏快取），依你的要求只做純函式，這 3 種留待另案。

本批新增 18 種：bokeh、starfield、panel、sticker、notify、callout、snow、matrixrain、ripple、gauge、clockdial、highlighter、candle、checklist、splitscreen、ptimeline、tunnel、blurzoom。每個都把示範用的字、數字、數量、顏色等改成參數（預設值＝原版）。

**驗證**
- 逐像素比對：27 種共 151 個時間點，預設參數下**全部 0 差異**。
- 比對本身可信：27 種在中間時間點的原版畫面都有內容（最少約 86 萬個非透明像素，不是兩張空白在比）；變異測試——把 snow 的雪花數少 1 片，比對立刻抓到 69 個位元組差異。
- 放進版面：試作專案把 gauge、checklist 用 g_fx 放進面板，`hyperframes check` 0 錯誤，抽幀確認透明底、主題色、字型都正常。
- 氣象案重建後動畫指紋仍為 2444 個、雜湊相同。

**注意事項**
- 預設比對只涵蓋「原版預設內容」；新開放的參數（例如換文字、換數量）沒有原版可比，只能靠目視。
- 部分效果原版用 JetBrains Mono、Unbounded 字型，本機沒有，會退回預設字型；比對時兩邊退回的字型相同，所以不影響 0 差異，但實際成片字型要另外決定。
- 原版 `t%T` 循環在移植版改成本地時間（比對範圍都在一個循環內，所以相同）；連續動態類（雪、星空、數位雨、隧道、水波）本身就是週期性，不受影響。
- 7 種圖鑑原本就是「示範用整張畫面」（panel、splitscreen、blurzoom、callout、notify、filmfx、stamp），要用在真實內容需要把示範畫面換掉；callout、filmfx、stamp 已有 `scene:false`／`paper:false` 之類的開關。

## 10. 數據圖表、轉場、文字標題三類批次移植（2026-10-22）

這三類尚未移植的純函式 56 種已全部移植，目前累計 **83 種**（手工 27 ＋ 半自動 56）。沒做的 4 種是有狀態的（sphere、ptext、softdiag、zoomtext）。

**做法：半自動移植工具** [port_effects.py](../tools/port_effects.py)：把圖鑑 HTML 裡 `DRAW[id]` 的繪圖指令**逐字**搬進 `catalog/fx/<id>.js`，只做三件機械式改動：①共用輔助函式（clear、scene、轉場 TR、顏色、緩動）改由 `K` 提供，底色與主題色可換、可透明；②示範文字（含中文或連續大寫字母的字串）抽成 `P.T[i]`；③字型抽成 `P.numFont／P.font／P.mono`。其餘包含 `t%T` 循環與所有數字都不動，所以預設參數下理論上一定與原版相同，並且仍逐像素實測。

**驗證**
- 逐像素比對：**83 種、599 個時間點，全部 0 差異**（含上一批 27 種）。
- 比對可信度：83 種原版都有動畫（沒有靜止畫面）、每個至少 22 種顏色；變異測試——換掉主色後 83 種裡 73 種的畫面立刻出現差異，證明比對抓得到差異（其餘 10 種本來就不用主題色）。
- 放進版面：試作專案用 `g_fx` 放進 donut、glitch、wipe，`hyperframes check` 0 錯誤，抽幀確認可見。另外三個測試案與睡眠案重新檢查皆通過；氣象案動畫指紋仍是 2444 個、雜湊相同。
- 建置只帶入這支片用得到的效果（氣象案頁面 350 KB，沒有變大）。

**限制（重要）**
- **半自動移植的 56 種，只有示範「文字」和「字型」是參數，數字與資料值（如圓環圖的 42%、折線的點、倒數的秒數、元素數量）仍寫死在程式裡。** 它們現在是「帶有示範資料的樣式卡」，直接拿來放真實資料會顯示示範數字。要用真實資料的效果，需要再逐個做第二輪「資料參數化」（像 counter、chart 那樣），並重新逐像素驗證。
- 文字抽取是啟發式：只抓含中文或連續大寫字母的字串，純小寫英文的示範文字（如 typewriter 的 `grid.wave(20, 12)`）沒有抽成參數。
- 轉場類效果的兩個畫面是示範文字「SCENE 1／SCENE 2」，實際使用要換成內容。
- 部分效果原版用 JetBrains Mono、Unbounded 字型，本機沒有會退回預設字型。
- 原版的 `t%T` 循環保留，所以效果會依原週期循環播放，不是「播完停住」。

## 11. 圖表類資料參數化（2026-10-22）

把第 10 節半自動移植的 8 個最常用圖表效果補做「資料參數化」，讓它們能放真實資料：[donut](fx/donut.js)、[linechart](fx/linechart.js)、[radar](fx/radar.js)、[waffle](fx/waffle.js)、[funnel](fx/funnel.js)、[heatmap](fx/heatmap.js)、[treemap](fx/treemap.js)、[countdown](fx/countdown.js)。這 8 個檔現在是手工維護，不要再用 `port_effects.py` 重新產生（工具會跳過已登記的效果，不會覆蓋）。

| 效果 | 新增的資料參數（預設＝原版） |
|---|---|
| donut | `data` 各段占比、`labels` 圖例、`colors` 各段顏色、`center`／`unit` 中間數字與單位、`span`、`rowGap` |
| linechart | `data` 各點高度（任意點數）、`span` |
| radar | `values` 各軸數值（軸數隨之改變）、`labels` 各軸名稱（選填）、`span` |
| waffle | `value` 比例、`cols`／`rows` 欄列、`unit`、`label` 說明、`span` |
| funnel | `stages` 各層 [名稱, 數值]（任意層數）、`stepW`、`rowH`、`gap` |

| countdown | `from` 起始數字、`per` 每個數字秒數 |

**驗證**
- 預設值逐像素：全部 83 種、599 個時間點仍 **0 差異**（8 個各 8 個時間點）。
- 參數有效：每個效果用自訂資料畫一張，與預設資料同一時間點比對，像素差異 2.6 萬～95 萬，全部大於 0；並目視確認（三段圓環、七點折線、五軸雷達含標籤、35% 人形點陣、三層漏斗、自訂矩陣熱力格、四塊自動版面樹狀圖、從 5 倒數）。
- 預覽頁：[_variants2.html](fx/_variants2.html)。

**已知限制**
- 漏斗的層數少、`stepW` 設大時，最後一層會很窄，文字會超出梯形（預覽圖的「成交 410」被切到）；建議 `stepW` 不超過 0.2，或縮短文字。
- 自訂資料只做了目視與「有差異」驗證，沒有原版可逐像素比對。
- 這 8 個效果的循環播放（`t%T`）與動畫節奏沿用原版，未改。
- 還沒做「效果選用機制」，所以目前要用這些效果仍需手動在 `g_fx` 指定效果 id 與資料。

- 驗證用伺服器請用 `fx/_serve.py`（不快取、只綁 127.0.0.1），並用 `http://127.0.0.1:8765` 開，不要用 `localhost`：本機常有別的程式佔著 localhost:8765，會讀到舊檔，造成假的「通過」。
